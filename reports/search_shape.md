# The shape of search: is human deliberation depth-limited / breadth-leaning, and does the value currency matter?

**Ref:** `R-SEARCH-SHAPE` · [Index](reference.md) · parent thread [(R-TREESEARCH)](treesearch.md) · sibling [(R-PRUNING)](pruning.md)

> **Status:** 📝 proposal — the plan + the discriminating tests. The thesis: every account ruled out so far
> manipulated the **reward** or the **stop**, holding the **search shape** fixed at the engine's
> narrow-deep, WDL-valued default. This report asks the orthogonal question — **does a deliberately
> *wider / shallower / optimistic* search, and/or a *centipawn* value currency, produce signals that track
> human RT better than the +0.34 legal-moves floor?** It names the real knobs in `build_tree.py` /
> `TeacherSearchConfig`, flags which are already exposed vs need code, sizes the regen, and pins the one
> discriminating test per knob.

---

## 1. The question, and why it is distinct from what we ruled out

### 1.1 What is settled, and the gap it leaves

The project has established ([report.md](../report.md), [(R-TREESEARCH)](treesearch.md)):

- **RT ≈ size(+0.31) − satisfaction(−0.31) + sharpness(+0.24)**; decision width (legal moves) is the
  dominant driver, ρ(legal, RT) ≈ **+0.34** unfiltered.
- Three generative accounts — **value-of-computation**, **value-pruning** (raw node count), **construal** —
  all collapsed to legal-moves (partial ≤ +0.04 controlling for legal moves).
- The engine search is **uniform-prior PUCT ⇒ UCB** (Stockfish has no policy head), which is
  **breadth-leaning**; and `max_depth=4` had been *forcing* the search wide. Moving to `max_depth=36`
  let pruned trees finally redeploy budget deep ([(R-PRUNING)](pruning.md) step 2).

The gap: **every ruled-out account left the search *shape* fixed.** We swept the cost shape (H1), the
uncertainty grade (H2), hindsight (H3), evaluator strength (H5), and the prune threshold — all
**reward-side or stop-side** manipulations on **one fixed search geometry**: AlphaZero PUCT with
`c_puct=1`, FPU=0, uniform priors, and a **WDL (win-prob) value scale**. We never asked whether *that
geometry* is the human-like one.

### 1.2 The two hypotheses

> **H-SHAPE (depth/breadth/exploration).** Humans are **depth-limited and breadth-leaning**: they look a
> few ply but weigh many candidates. A search whose *shape* is deliberately wider / shallower / more
> optimistic — higher `c_puct`, optimistic first-play-urgency, shallower `max_depth` — produces
> satisfaction / sharpness / Gain / stopping signals that track human RT **better** than the narrow-deep
> engine default. The strong form: people search like a **wide, shallow, optimistic** searcher.

> **H-CURRENCY (value representation).** The engine grades value in **WDL win-prob** — a bounded sigmoid
> where a +3 vs +5 cp gap is invisible in a won position. **Centipawns** are ~linear and unbounded.
> Every derived signal (satisfaction = #within-ε, sharpness = top1−top2, Gain) is **scale-dependent**.
> The hypothesis: the **cp** satisfaction/sharpness story tracks RT differently from the WDL one — i.e.
> humans represent value in one currency more than the other.

### 1.3 Why this is NOT a re-run of the ruled-out accounts

| Ruled-out account | What it varied | What it held fixed | This proposal varies the held-fixed thing |
|---|---|---|---|
| value-of-computation (H1–H3) | cost shape, uncertainty, hindsight | search geometry, value scale | search **geometry** (c_puct, FPU, depth) |
| evaluator strength (H5) | leaf-eval node budget N | tree **shape** (SF-1≡SF-100 bit-identical shape) | tree **shape** directly |
| value-pruning (R-PRUNING) | which leaves survive (ε), at fixed c_puct/FPU/WDL | exploration policy, value currency | the **exploration policy** + the **value currency** |
| construal | consideration-set definition | the searcher that builds it | the **searcher** (wide/shallow) |

The discriminator is **mechanistic**: pruning narrows the tree *after* the value landscape is read in WDL;
H-SHAPE changes *how the tree is grown in the first place* (which leaves get enumerated at all), and
H-CURRENCY changes *the scale the landscape is read in*. Neither is reachable by any cost/stop knob.

## 2. The exact knobs, with the CLI override that sets each

All trees are generated by `python -m cts.data.build_tree --config <core.yaml> --stage treegen ...` with
`--override <field>=<value>` (see `lmcos_tiny/analysis/slurm/prune_regen.slurm` for the canonical
invocation). The fields live on `BuildTreeConfig` (`lmcos_tiny/src/cts/data/build_tree.py`) and flow into
`TeacherSearchConfig` (`lmcos_tiny/src/cts/data/preprocess_gnn/teacher_targets.py`).

### 2.1 Already exposed — cheap, no code

| Knob | Field (real) | CLI override | Effect on shape | Mechanism (line ref) |
|---|---|---|---|---|
| **Exploration constant** | `c_puct` (default 1.0) | `--override c_puct=3.0` | higher ⇒ **wider** (exploration term dominates Q longer) | `_select_leaf_by_puct`, `parent_visit_scale = c_puct * sqrt(N+1)`, teacher_targets.py:1253 |
| **Depth cap** | `max_depth` (default 4; core.yaml=36) | `--override max_depth=4` (shallow) / `=8` | hard ply ceiling ⇒ **shallower** forces width | teacher_targets.py:1099, :1236 |
| **Budget** | `search_budget` (96) | `--override search_budget=32` | fewer expansions ⇒ smaller tree (a *size* control, not shape) | TeacherSearchConfig.search_budget |
| **Prune (shape via survivors)** | `prune_mode`/`prune_epsilon` | `--override prune_mode=rank --override prune_epsilon=4` | `rank` keeps top-k ⇒ fixed-width beam; `relative` = ε-ball | `_prune_children`, teacher_targets.py:1138 |

> **Note (a free width knob already lives in pruning).** `prune_mode=rank, prune_epsilon=k` keeps only the
> `k` best children per node — a **fixed-width beam search**. Sweeping `k ∈ {2,4,8,16}` is a clean,
> already-implemented "breadth dial" that holds budget redeploy logic identical to the pruning regen, and
> `prune_regen_analyze.py` already lists `rank2/rank4/rank8` dirs. This is the cheapest H-SHAPE probe and
> needs **zero new code**.

### 2.2 Needs new code — small, localized

| Knob | Where | Change | Risk flag |
|---|---|---|---|
| **First-play-urgency / optimism** | teacher_targets.py:1259 | `q_value = stats.q_value if stats.visit_count > 0 else 0.0` hardcodes **FPU=0**. Add `fpu: float = 0.0` to `TeacherSearchConfig` (+ `BuildTreeConfig` passthrough in `_build_quality_config`); use `else config.fpu`. Optimistic init = `fpu>0` (explore unvisited more ⇒ **wider**); pessimistic `fpu<0` ⇒ narrower-deep. | ~5 lines. Value is in [−1,1]; `fpu=+0.3` is "assume unseen moves are decent." |
| **cp value currency** | `_build_quality_config` + provider value source | The cp→value map **already exists**: `uci_score_to_value("cp", s) = clamp(s/1000, ±1)` (common.py:159). The SF provider forces WDL (`require_wdl=True`, stockfish.py:158). Add `value_currency: Literal["wdl","cp"]` to config; when `cp`, set `require_wdl=False` so `parse_root_value_features_from_lines` returns the **cp** value instead of `p_win−p_loss`. | ~15 lines, mostly plumbing. **This is the H-CURRENCY enabler.** See §5 risk: it may be a monotone reparam. |
| **Policy temperature / softened priors** | — | **NOT WORTH IT for SF.** Priors are **uniform** (StockfishDirectEvalProvider, `prior_source: uniform`), so `normalize_prior_scores` over a flat vector is temperature-invariant — flattening uniform does nothing. Temperature only bites if priors are non-uniform (the **lc0** provider has a policy head). | Skip unless we re-point to lc0 priors (out of scope; perceptual-adjacent). Flagged dead for SF. |

> **Decision:** the **cheap H-SHAPE sweep is `c_puct` × `max_depth` × `rank`-beam, all already exposed.**
> FPU and cp-currency are the two small code adds — both ≲20 lines, both localized. **Policy temperature is
> a no-op on SF's uniform priors and is dropped.**

### 2.3 The readout (no new code)

Per config, regenerate trees, then reuse the existing chain unchanged:
- **`compute_voc_signals.py`** → `sf_analysis/<set>/voc_signals.parquet` — emits `legal_moves`,
  `action_gap`, `n_good_{0.02..0.5}` (satisfaction at ε), `gain_costfree`, `oss__*` (step*),
  `softmax_voc__*`. The satisfaction/sharpness signals are **already computed from `oracle_final_root_q_values`**,
  so they automatically reflect whatever value currency the tree was built in.
- **`prune_regen_analyze.py`-style readout** — Spearman(signal, RT) + **partial | legal_moves**, bootstrap
  95% CI, DuckDB join on `processed_moves_nonzero`. Add the new `<set>` dirs to its `LEVELS` list.

The whole point: the readout is **invariant** to the knob — only the trees change. A config sweep is a
sweep over input directories, nothing else.

## 3. Feasibility (concrete)

Throughput and storage are measured in [(R-PRUNING)](pruning.md): **~1.36 trees/s/process at n=1**,
**~220 KB/tree** (less when pruned/narrow). The existing **250K n=1 md36 trees** (`n1md36`) are the
WDL / `c_puct=1` / FPU=0 / unpruned **baseline** — already on disk, free.

For a per-config readout, **50K trees is enough** (H5 ran on 50K; the RT correlations were stable to ±0.01
at 262K). Recommend **50K/config** for the sweep, scale only the winner.

| Sweep | Configs | Trees | Wall (50K @ 1.36/s, 20 array tasks) | Storage | Code |
|---|---|---|---|---|---|
| **rank-beam width** (k=2,4,8) | 3 | 150K | ~30 min/config | ~30 GB total (narrow ⇒ small) | **none** (exists) |
| **c_puct** (0.5, 3.0, 8.0) | 3 | 150K | ~30 min/config | ~33 GB | none |
| **max_depth** (4, 8 — shallow) | 2 | 100K | ~30 min/config | ~22 GB | none |
| **FPU** (+0.3, +0.6, −0.3) | 3 | 150K | ~30 min/config | ~33 GB | ~5 lines |
| **cp-currency** (×{c_puct=1, c_puct=3}) | 2 | 100K | ~30 min/config | ~22 GB | ~15 lines |
| baseline | — | (0) | reuse `n1md36` | 0 | — |
| **TOTAL** | 13 | **~650K** | **~6–7 h** wall, 20-way array | **~140 GB peak** | ~20 lines |

> **Result (feasibility):** the whole search-shape program is **~650K trees ≈ a half-day** of CPU array,
> **~140 GB** (within the 1.7 TB free on `/scratch`, and below the pruning regen's own 250–330 GB peak).
> The **rank-beam, c_puct, and max_depth arms are runnable today with zero code** — start there. FPU and
> cp need ~20 lines combined. Reuse `prune_regen.slurm` verbatim, swapping the `--override` set and `OUTDIR`.

A concrete launch (mirrors the prune regen pattern):

```bash

sbatch --array=0-19 --export=ALL,EXTRA="--override c_puct=3.0",\
  OUTDIR=$SCRATCH/sf_trees/n1md36_cpuct3,LANE_END=50000 \
```

## 4. Predictions, and the ONE discriminating test per hypothesis

The bar is the same for all: **beat the bare legal-moves floor (ρ≈+0.34, partial|legal > +0.05).** The
ruled-out accounts all died at partial ≤ +0.04. A knob *wins* only if some signal it produces clears that.

### 4.1 H-SHAPE — predictions

| Config move | Predicted effect on signals | Predicted RT correspondence |
|---|---|---|
| **wider** (c_puct↑, FPU↑, rank-k large) | tree enumerates more leaves ⇒ `n_total`/satisfaction inflate **toward legal-moves** | RT corr **rises but via legal-moves** — partial|legal stays ~0 (the **null** prediction) |
| **shallower** (max_depth 4/8) | forces width *at fixed budget*; satisfaction/sharpness read off a **shallow** value landscape | **IF humans are depth-limited**, shallow-tree sharpness should match RT *better* than deep — partial|legal **> +0.05** |
| **narrower-deep** (c_puct↓, FPU<0, rank-2) | budget drives deep on few lines; sharpness from deep reads | partial|legal expected **≤ 0** (humans aren't deep) |

> **THE discriminating test for H-SHAPE.** Build the **same** decision-difficulty signal (sharpness =
> top1−top2, satisfaction = #good within ε) at a **shallow** geometry (`max_depth=4`, c_puct moderate) and a
> **deep** geometry (`max_depth=36`, c_puct low). The shallow signal reads value a few ply out; the deep
> one reads it 19 ply out. **Partial-out legal_moves from each.** H-SHAPE wins **iff the *shallow*
> sharpness/satisfaction beats legal-moves (partial > +0.05) while the *deep* one does not** — that is
> direct evidence humans grade options at human depth, not engine depth. If *both* die at partial ≈ 0, the
> shape is irrelevant and width is the whole story (consistent with everything prior).

The `c_puct`/FPU/rank-width arms are the **collinearity control**: if widening only raises the *raw* RT
correlation while the partial|legal stays flat, the win (if any) is depth, not breadth — exactly the
falsifiable separation H-SHAPE needs.

### 4.2 H-CURRENCY — prediction and the discriminating test

WDL compresses gaps near 0 and ±1; cp is linear. So **satisfaction** (#moves within ε of best) and
**sharpness** (top1−top2) are computed on different geometries:

- In a **won** position (eval +4 to +6), several moves are "winning" ⇒ **WDL satisfaction is high**
  (everything ≈ p_win 0.95), but **cp satisfaction is low** (a +6 vs +4 gap is large in cp). If humans
  *relax* in won positions (think less when clearly winning), **WDL** matches RT; if they still
  discriminate among winning moves, **cp** matches.
- The signs predict: WDL-satisfaction should track the **−0.31 satisfaction** effect (good-enough ⇒ stop);
  cp-satisfaction may not, because cp keeps "winning but not best" moves *out* of the good set.

> **THE discriminating test for H-CURRENCY.** Regenerate one arm in cp, recompute `n_good_ε`
> (satisfaction) and `action_gap` (sharpness) in both currencies on the **same FENs**, and compare
> **Spearman(satisfaction, RT)** WDL-vs-cp **stratified by |root eval|** (decided vs balanced positions).
> The currencies are a **monotone reparam in balanced positions** (Spearman blind, §5) — so the test must
> live in the **decided** stratum (|eval|>2), where the sigmoid saturates and the WDL/cp *rankings of the
> satisfaction count actually diverge*. H-CURRENCY wins iff the two currencies give **different-signed or
> non-overlapping-CI** satisfaction↔RT slopes *in the decided stratum*. If they agree everywhere, the
> currency is a wash (the honest null).

## 5. Risks (the two that can kill each hypothesis)

> **Risk 1 — widening just re-inflates legal-moves (H-SHAPE).** A wider search enumerates more leaves, and
> `n_total`/satisfaction are already **0.857-collinear with legal-moves** ([(R-PRUNING)](pruning.md)). So
> "wider tracks RT better" is the *expected null* — it rises *through* the floor, not past it. **Mitigation:
> the partial|legal_moves IS the test**, not the raw ρ. Only a partial > +0.05 counts. The depth contrast
> (§4.1) is the part that can clear the floor because depth changes *which* value the leaves carry, not how
> many there are.

> **Risk 2 — cp-vs-WDL is a monotone reparam Spearman ignores (H-CURRENCY).** `value = p_win − p_loss` is a
> **monotone** function of cp within a position (both rise with engine score). For any signal that is a
> *rank* over moves in one position — and the per-position best move is currency-invariant — **Spearman is
> blind to the reparam.** Where currency bites is **counts across the sigmoid's saturating region**
> (#moves within an *absolute* ε): ε=0.1 in WDL ≠ ε=0.1 in cp, and the count rankings diverge **only when
> the sigmoid saturates** (decided positions). **Mitigation:** restrict the H-CURRENCY test to the decided
> stratum and use an *absolute* ε on each scale; if the satisfaction counts still rank-agree there, declare
> currency a no-op and move on. Do **not** report a raw cp-vs-WDL ρ difference without the stratification —
> it would be a reparam artifact.

> **Risk 3 — the reward-to-planning filter (shared with R-PRUNING).** The filter selects monotone-gain
> positions, which removes reversals — exactly where shallow ≠ deep would show. Run the H-SHAPE depth
> contrast on the **unfiltered** population (as `compute_voc_signals.py` defaults, `VOC_FILTERED=0`) so the
> shallow/deep divergence is not pre-suppressed.

> **Risk 4 — FPU interacts with the WDL zero-point.** FPU=0 means "unvisited child Q = 0" = "drawish" in
> WDL (`value=0` ⇔ p_win=p_loss). In cp, value=0 is also "equal," so FPU=0 is coincidentally calibrated;
> but `fpu=+0.3` means "+0.3 win-prob optimism," a different magnitude in cp. **Keep FPU sweeps within a
> single currency**; do not cross FPU × currency in one cell.

## 6. Open questions

> **Open question (depth is the real lever, breadth is the decoy).** If §4.1's depth contrast clears the
> floor, the headline is "humans grade options at ~human depth (a few ply), not engine depth (19 ply)" —
> the first signal that *beats* legal-moves by being **mis-specified in the human direction**, not the
> engine direction. That would be the project's first non-width win. It is **untested**.

> **Open question (does cp ever matter?).** If currency is a wash even in decided positions, it confirms
> humans (like the engine's WDL) treat "winning" as a satisficing absorbing state — which would itself be a
> clean result supporting the satisficing story. Either outcome is informative; the null is publishable.

> **Open question (compose shape with pruning).** The cleanest "human-like searcher" is **wide-shallow +
> value-pruned** (rank-beam k small, max_depth shallow): consider few-but-plausible moves, a few ply. If
> any single knob clears the floor, the natural follow-up is the **composite** geometry, fit with the
> 1–2-param satisficing consideration-set model from [(R-PRUNING)](pruning.md) step 4.

## 7. Staged plan (in priority order)

1. **rank-beam width sweep (k=2,4,8), zero code, 30 min/arm.** Free width dial; confirms Risk-1 null
   (raw ρ rises, partial|legal flat). Establishes the collinearity baseline before spending on depth.
2. **max_depth depth contrast (4, 8 vs 36), zero code.** *The* H-SHAPE test (§4.1). Run unfiltered.
   Go/no-go on whether shallow sharpness/satisfaction beats the floor.
3. **c_puct + FPU exploration sweep** (FPU = ~5 lines). Separates breadth from depth as the lever.
4. **cp-currency arm** (~15 lines). H-CURRENCY test (§4.2), decided-stratum only.
5. **If any arm clears partial|legal > +0.05:** scale the winner to 250K, fit the satisficing
   consideration-set model (R-PRUNING step 4), compose with pruning.

> **Success = some shape/currency signal has partial-controlling-for-legal-moves > +0.05 with a 95% CI
> excluding the floor** — the same bar the ruled-out accounts all failed. Anything less is another
> re-description of decision width, and should be reported as such.
